# Textiles Move ERP — instructions for AI coding assistants

(Same content as CLAUDE.md, for Codex / Cursor / other AI tools. Keep both in sync.)

## What this is
A BYU class mini-ERP for Textiles Move, a knitwear manufacturer in Lima, Peru. It is graded in a **live demo**:
Dr. Wright may change any input and ask to see the result update, so **every number shown must be computed from
stored data** — never hard-code a total, rate or metric in the UI.

## Architecture
- `supabase/01_schema.sql` — tables, row-level security, realtime. Re-running it ERASES data.
- `supabase/02_logic.sql` — one PL/pgSQL function per business event (`post_sale`, `fulfill_sales_order`,
  `process_return`, `transfer_stock`, `adjust_stock`, `create_po`/`send_po`/`receive_po`/`pay_po`,
  `create_wo`/`issue_wo`/`complete_wo`/`cancel_wo`, …). Safe to re-run (`create or replace`).
- `supabase/03_seed.sql` — GENERATED by `scripts/build_seed.py` from the company workbook. Don't hand-edit.
- `src/lib/calc.js` — all derived numbers (ROP, EOQ, periodic review, MRP records, supplier scorecard,
  production metrics, P&L). Pure functions, tested in `scripts/test/calc.test.mjs`.
- `src/lib/data.jsx` — loads tables, realtime refresh, `call(rpcName, args)` for transactions.
- `src/pages/*.jsx` — one file per module. `src/components/ui.jsx` — shared UI (Page, Card, Modal, ItemSearch, Barcode…).
- Hosting: GitHub Pages via `.github/workflows/deploy.yml` on push to `main`. Database/auth: Supabase.

## Git workflow (required — several teammates work at the same time)
- **Never commit or push directly to `main`.** `main` is protected and auto-deploys the live site.
- Start every task from the latest main: `git checkout main && git pull`, then create a branch
  named `<yourname>/<short-change>` (e.g. `alex/returns-chart`).
- Commit on that branch, push the branch, and open a **pull request** into `main`
  (with `gh pr create` if the GitHub CLI is installed, otherwise give the human the
  "Create pull request" link GitHub prints after the push).
- Keep each pull request to one feature. If GitHub reports conflicts, merge the latest `main` into the
  branch, resolve them keeping both teammates' changes, re-run `npm run build` and `npm run test:calc`, push again.
- Shared files (`src/lib/calc.js`, `src/components/ui.jsx`, `supabase/02_logic.sql`) are edited by
  several people — change only what the task needs there, and tell the human to mention it to the team.
- Merging is done by a human on GitHub after the checks pass; don't merge on your own unless asked.

## Rules
1. **Writes go through SQL functions only.** The browser never inserts/updates tables directly. A new kind of
   transaction = a new function in `02_logic.sql` that (a) checks `_require_staff()`, (b) changes stock only via
   `_move()` (which blocks negative stock and records an `inv_moves` row), (c) posts **balanced** ledger lines
   via `_gl()` (debits = credits), (d) returns `jsonb` with the document `id`.
2. **Derived numbers live in `calc.js`** (or a SQL function), never typed into the UI.
3. Money is Peruvian soles (S/). Retail `sale_price` includes 18% IGV; stored `unit_price` on sales lines is before IGV.
   Business dates are Lima time (`America/Lima`, UTC-5) — use helpers in `calc.js`.
4. Keep the **"How this works in the ERP"** panel on each page accurate when you change behaviour — the team
   uses it to explain ERP/MRP concepts in the demo.
5. MRP must keep matching the Chapter 10 slide format/logic (Gross Req, Scheduled Receipts, Projected On Hand,
   Net Req, Planned Order Receipts, Planned Order Releases; L4L/FOQ; lead-time offset). The slide examples are tests.
6. After changing SQL, remind the human to paste `02_logic.sql` (or the changed function) into the Supabase SQL
   editor — SQL is not deployed by GitHub Actions.
7. Before finishing: `npm run build` must pass and `npm run test:calc` must pass. If PostgreSQL is installed,
   run `npm test` (also runs the 58 database transaction checks in `scripts/test/transactions.sql`); add a check
   there for any new transaction.
8. Don't commit secrets. `src/config.js` holds only the public Supabase URL and anon key.

## Local testing without Supabase (optional)
With PostgreSQL installed: `bash scripts/test/run.sh`, then `node scripts/dev-backend.mjs` and
`npx vite --mode devbackend`. The dev backend is a minimal stand-in (no realtime).
